react-flow 11
CANVAS SURFACE
The integrator's drawing board. Drag states, connect transitions, double-click to configure. Every interaction serialises to canonical JSON.
What it does
Drag-and-drop state nodes from palette
Draw transition edges between states
Display context-sensitive properties panel
Serialise canvas layout to workflow JSON
Read-only diagram mode for AP operators
What it does NOT do
Execute workflow logic
Send notifications
Store state
⚡
XState v5
EXECUTION ENGINE
The brain of the workflow. Reads the JSON the canvas produces, evaluates every guard and action, produces the next state. Stateless between requests.
What it does
Evaluate transition guards
Fire entry and exit actions
Handle delayed SLA transitions
Run parallel approval tracks
Invoke async services (OCR, GL, anomaly)
Produce persisted snapshot for PostgreSQL
What it does NOT do
Hold state in memory
Send emails or webhooks
Draw diagrams
🔷
Stately Studio
DESIGN-TIME VISUALISER
Visual design and simulation for the integrator before going live. Draw the workflow, simulate test invoices, export clean XState JSON. Design-time only — never runs in production.
What it does
Visual state machine designer
Simulate workflow with test events
Export XState JSON directly
Validate machine definition before activation
What it does NOT do
Run in Docker or production
Replace react-flow canvas
Store workflow state

05
10 Database Stability Rules
Invariants — not guidelines — enforced by code review and PostgreSQL roles
1
PostgreSQL is the only source of truth. No cache, no in-memory object, no Redis key is authoritative for workflow state.
2
XState is stateless between requests. Create actor, evaluate event, get snapshot, discard actor. Never kept alive between calls.
3
State + history + audit in ONE transaction. If the state changes, the history record exists. They commit together or not at all.
4
n8n calls happen AFTER commit. Never inside the transaction. If n8n is down, the invoice state is still correct. BullMQ retries the notification.
5
Optimistic lock on every UPDATE. AND version = $expected_version on every workflow_state write. Zero rows updated means retry.
6
Terminal invoices never transition. Check is_terminal before XState. Approved, Rejected, Reconciled are sealed forever.
7
FOR UPDATE SKIP LOCKED on every snapshot load. Prevents two simultaneous events on the same invoice from both succeeding.
8
Timer cancellation in SAME transaction as exit. Cancel BullMQ job and update workflow_timers atomically when leaving a timed state.
9
No DELETEs on workflow tables. REVOKE DELETE enforced at PostgreSQL role level. Only a privileged archive job can move rows after 7-year retention.
10
All workflow changes through WorkflowEngine.advance() only. No direct SQL writes to workflow_state from any module other than MOD-04.
